> **把跨会话记忆整理成分门别类、简短可读的 Markdown 活文档**，并在 DeepSeek Harness 的界面里给一个专属页面。

![记忆册：一个分类一个 md 文件，三层组织，配一个专属页面](docs/assets/hero.zh.svg)

---

## 它解决什么问题

几乎所有 AI 记忆方案都在解决「**怎么记得更多、取得更准**」。

记忆册反过来，只解决一件事：**让这份记忆短到有人愿意读**。

一条记忆就是一句话，整本读一遍不超过两分钟。它不会随对话轮次无限膨胀——因为它是被**改写**的，不是被**追加**的。

---

## ✨ 有什么不一样

| | 常见的做法 | 记忆册 |
|---|---|---|
| **增长方式** | 只增不减，靠人去清理 | **每次通读全文改写**：合并、缩略、删除、新增。长度由内容决定，不由历史决定 |
| **模型角色** | 记录员——发现新的就追加一条 | **编辑**——像维护一份活文档那样重写整本 |
| **组织方式** | 一个平铺的列表，或写死的分类 | **三层**：分类 → 小节 → 条目。分类和小节都由模型按主题自由增删 |
| **数据形态** | 数据库 / 向量库 / 私有格式 | **纯 Markdown 文件**。可以用任何编辑器打开、手工改、进版本控制 |
| **规模控制** | 满了才报错 | **容量触发整理**：分类超 12 条或整本超 40 条，自动下强制整理令 |
| **关闭怎么办** | 只能卸载 | 页面上一键**写入总开关**，关掉之后既不读取也不写入 |

一句话：**别的方案在解决「记什么」，它在解决「怎么读得下去」。**

## 🚀 快速开始

### 1. 安装

```sh
dsh plugin --profile desktop add @yansera/dsh-living-memoir
```

> 把 `desktop` 换成你的 profile 名（Web 端通常是 `web`）。
> `dsh` 是 DeepSeek Harness 自带的 CLI（桌面客户端在 `<安装目录>\resources\runtime\cli\bin\dsh.cmd`）。

**从源码装**（开发用）：

```sh
dsh plugin --profile desktop add 'file:D:\path\to\dsh-memoir'
```

### 2. 重启客户端

**这一步不能省**：DSH 只在**安装插件那一刻**加载代码，之后改文件它不认。关窗口不算退出，要**完全退出**再打开。

### 3. 打开记忆册

侧边栏会出现「**记忆册**」图标。点一下，主区域整个切成记忆册——左边是分类，右边是条目。**左上角的「← 返回对话」**随时回到会话。

### 4. 开始用

不用做任何配置。之后：

- **模型会自己记**：你说出持久偏好、定下项目决策、纠正它的时候，它会调用 `memoir_note` 写进去
- **你也能手写**：点「记一条」，或者**直接编辑 `$DSH_HOME/memoir/` 下的 md 文件**（改完刷新页面就能看到）
- **每轮对话自动整理**：一轮结束安静 20 秒后，后台通读整本并改写

**想让它停下来？** 页面右上角 **⚙** → 关掉「**记忆写入**」。关掉之后不读也不写，一条都不会动。

## 🧱 三层结构，最多三层

```
# 在做的事                          ← 第 1 层：分类。结构与数量由模型按内容决定

<!-- 项目、当前阶段 · 可直接手工编辑 -->

## 记忆册                          ← 第 2 层：小节。按项目 / 主题自由铺开

- 把跨会话记忆整理成分类简短的 md 活文档    ← 第 3 层：条目。到此为止
  <!-- memoir id=a1b2c3d4 | imp=4 | at=2026-10-07 | src=自动提炼 -->

## 修仙：进化网络

- 用基因突变与自然选择长出承载语义的拓扑
```

| 层 | 写法 | 谁决定 |
|---|---|---|
| **分类** | 一个 md 文件 | 模型按主题自由增删，代码里没有写死的清单 |
| **小节** | `## 项目名` | 同一个项目的一切都归它名下；不合适就不写 |
| **条目** | `- 一句话` | 到此为止，不再往下分 |

**为什么按主题分而不是按类型分？** 因为找东西的时候，人想的是「这是哪个项目」，不是「这算决策还是算进展」。按类型分会把同一个项目的信息切碎到几个抽屉里。

装好时会铺五个起头分类：**关于用户 · 偏好与规则 · 正在做的事 · 定下的决策 · 关于助手**。这只是起头——你用不着它们就删掉。

## ✍️ 三条写入通道，一本活文档

![三条写入通道汇入一本活文档；容量超限时触发强制整理](docs/assets/pipeline.zh.svg)

| 通道 | 怎么触发 | 谁在写 |
|---|---|---|
| **模型工具** | 模型判断什么值得记 | `memoir_note` / `memoir_recall` / `memoir_forget` |
| **页面手写** | 点「记一条」，或直接改 md | 你 |
| **自动改写** | 每轮对话结束后 | 模型通读整本、交出改好的完整版本 |

> 前两条是**追加**，第三条是**改写**。第三条才是这套东西的核心——它保证文档不会只涨不消。

## 🔄 每轮结束自动改写

一轮对话安静下来之后（默认等 20 秒），后台做的是**改写整本记忆册**：

> 模型的输入是「记忆册现在的全部内容 + 这段新对话」，要交出的输出是**改写后的完整版本**——该合并的合并、该改写的改写、该删的删、该加的加，分类也能增删成合适的形状。

所以它更像一个**编辑**在维护一份活文档，而不是一个记录员往日志里追加。

**几条防呆**：

- **按会话存游标**——只消费上次之后的新事件，同一段不会被反复改写
- **失败不推进游标**——下一次轮次结束会重试同一段
- **内容太少就跳过**（默认 400 字符），但游标照常推进
- **全局串行**——多个会话同时收尾时请求排队，不会一拥而上
- **两道安全网**：解析不出分类就什么都不写；条目总数骤减一半以上（原本 ≥6 条时）直接拒绝这次改写、保留原样

取不到 `llm` 服务（宿主没配模型）时整条路静默跳过，工具和页面照常工作。

### 容量触发整理

光靠「每轮改写」不够——它只会小修小补，条数照样往上涨。所以加了两道阈值：

| 阈值 | 默认 | 意思 |
|---|---|---|
| `pageEntryLimit` | 12 | 一个分类超过这么多条 |
| `bookEntryLimit` | 40 | 整本超过这么多条 |

**只要有一条踩线**，这次改写就会额外收到一条**强制整理令**，写明现在多少条、哪几个分类超了，并要求做三件事：

1. **合并**——同一件事、同义或高度相关的条目合成一句
2. **缩略**——啰嗦的长条目压成一句话，只留结论
3. **加小节**——条目多的分类用 `##` 拆开，不要二十多条平铺

**没踩线时不会加这段**，改写保持轻量。

## ⚙️ 设置面板

页面右上角的 **⚙**：

### 记忆写入总开关

关掉之后**既不读取也不写入**：

- 系统提示里不再注入记忆
- 三个工具全部拒绝执行
- 页面和 HTTP 接口的写入一律返回 403
- 每轮结束的自动改写停跑

适合「这段对话别记」的场景，比卸载插件轻得多。

### 改写用哪个模型

打开 ⚙，「改写用的模型」下面第一个下拉**直接列出宿主已经注册好的模型**——点一下，下面两个框自动填好。

**你不需要知道 provider 叫什么、模型 id 怎么写。** 下拉里的每一项来自宿主的：

```ts
ctx.llm.listProviders()          // 所有已注册的 provider
ctx.llm.listModels(provider)     // 每个下面有哪些模型
```

所以不管你想用哪种，只要**在 DSH 里关联好了**，它就在那个下拉里：

- **DSH 自带的**——比如 `deepseek-official` 下的 `deepseek-flash`
- **本地模型**——你在 DSH 里接好的本地推理服务（Ollama、llama.cpp 之类）
- **第三方 API**——任何 OpenAI 兼容端点，只要在 DSH 里配成 provider

下拉下面还有两个**手填**的输入框，宿主没列出来的（比如动态生成的模型名）可以走那里。**两条路都通。**

| 字段 | 说明 |
|---|---|
| **服务商** | 留空 = 跟 Agent 的默认模型走；也可以从下拉里选 |
| **模型** | 留空 = 跟默认；也可以从下拉里选 |
| **思考程度** | `关闭` / `低` / `高` / `最高` / `不发送` |

> 插件**自己不发起任何网络请求**，全部走宿主的 `llm` 能力。所以能选什么，取决于你在 DSH 里接了什么。宿主一个模型都没注册时，下拉会显示提示，不会是一片空白。

**为什么默认关掉思考？** 改写是**整理**不是**解题**。实测过：思考型模型会把输出预算烧在推理上，等该吐正文时预算已经没了——表现为「请求成功但正文块一个都没有」。关掉之后同样的预算全给了正文。

## 🌍 语言：界面语言 与 记忆语言

这两件事**是分开的**，各有各的开关——很多人会以为是一回事：

| | 管什么 | 默认 |
|---|---|---|
| **界面语言** | 按钮、标签、提示这些**界面文案** | `en`（English） |
| **记忆语言** | **存进 md 里的字**，包括分类名和小节名 | `en`（English） |

### 界面语言

支持 **简体中文 · English · Français · Deutsch · 日本語**。

- **默认英文**（面向公开分发）
- 也可以选**跟随宿主**——DSH 用哪个语言，插件就用哪个
- 切换是**纯前端**完成的，不用重启，也不用回服务端

### 记忆语言

设了之后，改写提示词里会多一条命令：

> 【语言】这份记忆册的内容一律用 X 写，分类名和小节名也是，不要混用其他语言。

**它不影响界面**——界面该是什么语言还是什么语言。

- **默认英文**
- 选「**不限制**」就不下这条命令，让模型跟着对话语言走
- 没有 `llm` 服务时这条命令无从生效——那时压根不会触发改写

## 🔧 配置

所有部署可变项都走 `cordis.patch.yml`（或 profile 里的覆盖层），**代码里没有写死的阈值**。

```yaml
- id: memoir
  name: '@yansera/dsh-living-memoir'
  config:
    memoryDir: ''              # 留空 = $DSH_HOME/memoir
    injectIndex: true          # 是否注入「记忆目录」
    maxInjectEntries: 12       # 注入最多几条
    autoDistill: true          # 每轮结束自动改写
    distillDebounceMs: 20000   # 改写前的安静等待（毫秒）
    distillMinChars: 400       # 少于这么多字符就跳过
    distillMaxItems: 60        # 整本条目上限（提示模型控制规模）
    distillMaxTokens: 8000     # 输出预算下限（会按记忆规模自动往上抬）
    distillReasoningEffort: off # 改写不需要推理，关掉思考把预算全留给正文
    memoryLanguage: ''         # 记忆内容用哪种语言写；留空 = 不限制
    pageEntryLimit: 12         # 单个分类超过这么多条 → 触发强制整理
    bookEntryLimit: 40         # 整本超过这么多条 → 触发强制整理
```

**改完配置要重启**：配置改动跟代码改动一样，热加载只在安装插件那一刻发生。

### 页面上改的设置

`cordis.patch.yml` 管的是**部署级**配置；页面上 ⚙ 改的是**运行时设置**，存在记忆库目录的 `.settings.json` 里——跟记忆数据放一起，换 profile 不丢，升级插件也不会覆盖。

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 写入总开关；关掉既不读也不写 |
| `distillProvider` | `""` | 改写用的服务商；留空跟 Agent 默认 |
| `distillModel` | `""` | 改写用的模型；留空跟默认 |
| `distillReasoningEffort` | `""` | 覆盖配置里的思考档位 |
| `locale` | `"en"` | 界面语言；`""` = 跟随宿主 |
| `memoryLanguage` | `"en"` | 记忆内容语言；`""` = 不限制 |

**默认值是英文界面 + 英文记忆**（面向公开分发）。但**它只在文件不存在时生效**——一旦文件存在就以文件为准，所以你选「跟随宿主 / 不限制」会**如实存成空串**，不会被默认值盖回来。

## 📂 存储格式

```
$DSH_HOME/memoir/          ← 默认位置，可用 memoryDir 改
├── .order                 ← 分类顺序（一行一个 id）
├── .settings.json         ← 页面上改的设置
├── user.md                ← 一个文件 = 一个分类
└── ...
```

**没有数据库、没有索引、没有缓存**。每次读写都直接落盘——文件都很小，换来的是「手工改了文件，页面刷新立刻就能看到」。

**手工编辑规则**：

| 行 | 含义 |
|---|---|
| `# 标题` | 分类的中文名（文件头，跳过） |
| `## 小节名` | 第二层小节；其后的条目都归它 |
| `- 内容` | 一条记忆 |
| `  <!-- memoir … -->` | 上一条的元数据（可以整行省略） |
| 缩进 2 空格以上的行 | 上一条的续行 |
| 其它（空行、段落、`###`） | 排版，忽略 |

**id 是内容派生的**：内容不变，id 就不变。所以全量改写不会打断页面上的定位。

## ❓ 常见问题

**问：它和系统里其他记忆功能会冲突吗？**
不会。记忆册只管**长期、宏观**那一层——用户是谁、助手是谁、在做什么、定过什么大方向决策；短期与过程性的内容（技术细节、踩坑、进度流水）不归它管，也不会写进来。记忆存在自己的目录里，跟别的系统互不读写。

**问：为什么我的记忆册里看不到技术细节？**
刻意的。技术细节会让「关于用户」那张卡片被二十条命令淹没，最后谁也不看。它们属于另一个记忆系统。

**问：改完 md 文件要重启吗？**
不用。读取是每次实时读盘的，刷新页面就能看到。

**问：关掉写入开关会丢数据吗？**
不会。关掉只是停止读写，文件原样留在磁盘上，重新打开就继续。

**问：它会不会偷偷发网络请求？**
不会。除了用宿主的 `llm` 能力做改写，它不发起任何自己的网络请求，不读记忆库目录以外的文件，不收集遥测。

**问：记忆内容会发给模型服务商吗？**
**会**——记忆目录会注入到每次模型请求里，改写也会把整本发出去。所以**不要往记忆库里放密码、token、私钥**。详见 [SECURITY.md](SECURITY.md)。

测试全部离线：不依赖 DSH 宿主，也不碰任何真实 profile。

**改完源码之后**（Windows）：

```powershell
& .\scripts\sync.ps1
```

pnpm 用 `file:` 装本地包时是硬链接，编辑源码会断开链接、安装位置的副本就不再更新——所以必须同步，然后重启客户端。
