# 记忆册（dsh-memoir）

把跨会话记忆整理成**分门别类、简短可读的 Markdown**，并在 Web GUI 的侧边栏给一个专属页面。

> 包名 `@yansera/dsh-memoir` · MIT · 199 项离线自测

它盯的是记忆最容易烂掉的那一面：不是「记不住」，而是**记得太多太长、没人愿意读**。所以这里的**一条记忆就是一句话**，组织成**最多三层**（分类 → 小节 → 条目）。

## 记忆库长什么样

默认在 `$DSH_HOME/memoir`（本机即 `D:\dsh\memoir\`）。**一个 md 文件就是一个分类**，而分类不写死在代码里——目录里有哪些 `.md`，就有哪些分类。装好时会铺这么一套起头：

| 文件 | 分类 | 放什么 |
|---|---|---|
| `user.md` | 关于主人 | 身份、环境、习惯、称呼 |
| `preferences.md` | 偏好与规则 | 希望我怎么做、不许怎么做 |
| `projects.md` | 正在做的事 | 项目、当前进展、下一步 |
| `decisions.md` | 定下的决策 | 选了哪条路、为什么 |
| `lessons.md` | 踩过的坑 | 症状 → 原因 → 解法 |
| `self.md` | 关于我自己 | 我的定位、自称、风格 |

但这只是**起头**。模型可以随时新建一个分类（比如给某个大项目单开一个文件），也可以把没用的整个删掉——文件名就是分类 id，首行 `# 标题` 是中文名，紧跟的注释是它的说明。展示顺序记在目录里的 `.order`（一行一个 id）。

文件本身长这样，**可以直接手工编辑**——三层，最多三层：

```markdown
# 在做的事                          ← 第 1 层：分类。要大而少，三个上下就够

<!-- 项目、当前阶段 · 由 dsh-memoir 维护，可以直接手工编辑：加一行 “- 内容” 就等于加一条记忆 -->

## 记忆册                          ← 第 2 层：小节。按项目 / 主题自由铺开

- 把跨会话记忆整理成分类简短的 md 活文档    ← 第 3 层：条目。到此为止
  <!-- memoir id=a1b2c3d4 | imp=4 | at=2026-10-07 | src=自动提炼 -->

## 修仙：进化网络

- 用基因突变与自然选择长出承载语义的拓扑
```

- 第 1 层要**大**：别把每个话题都开成一个分类
- 第 2 层**自由**：同一个项目的东西都归到它名下；没有合适的小节就不写，条目直接挂在分类下
- 第 3 层就是**一句话**：正文要短（上限 400 字）
- 紧跟条目的 `<!-- memoir … -->` 是元数据注释，渲染时不显示，手工写的时候可以整行省略
- 标题、说明、普通段落都会被忽略，所以往文件里写笔记不会污染记忆

## 三种写入方式

1. **模型用工具记** —— `memoir_note` / `memoir_recall` / `memoir_forget`。模型在会话里判断什么值得记。
2. **在页面上写** —— 侧边栏的「记忆册」图标，点一下**主区域整个切成记忆册**（0.2.0 原生的「全局面板」，跟会话视图并列切换，不是浮在对话上的弹窗）；侧边栏底部还留了个入口可以开浮层。打开默认是**「全部」视图**：一屏看完所有记忆，每条标着它属于哪一类；点左边某一类可以只看那一类，新增记忆也在那里（「全部」视图下不给新增，免得不知道该记进哪一类）。
3. **直接编辑 md** —— 改了立刻生效，页面刷新就能看到。

模型用 `memoir_note` 记的时候，同分类下**完全相同**、**近义**（差一两个字）或**一条包含另一条**的会被自动合并成一条，保留更完整的那句；改写模式不需要这层保护——它本来就是整盘重写。

## 每轮结束自动改写

一轮对话安静下来之后（默认等 20 秒），后台做的是**改写整本记忆册**，而不是往后追加：

> 模型的输入是「记忆册现在的全部内容 + 这段新对话」，要交出的输出是**改写后的完整版本**——该合并的合并、该改写的改写、该删的删、该加的加，分类也能增删成合适的形状。

所以它更像一个**编辑**在维护一份活文档，而不是一个记录员往日志里追加。文档长度由内容决定，不由历史决定。

几条防呆：

- **按会话存游标**——只消费上次之后的新事件，同一段不会被反复改写；
- **失败不推进游标**——下一次轮次结束会重试同一段；
- **内容太少就跳过**（默认 400 字符），但游标照常推进；
- **全局串行**——多个会话同时收尾时请求排队，不会一拥而上；
- **两道安全网**：解析不出分类就什么都不写；条目总数骤减一半以上（原本 ≥6 条时）直接拒绝这次改写、保留原样。

取不到 `llm` 服务（宿主没配模型）时整条路静默跳过，工具和页面照常工作。

### 涨过头就自动整理

光靠「每轮改写」不够——它只会小修小补，条数照样往上涨。所以加了两道**容量触发**：

| 阈值 | 默认 | 意思 |
|---|---|---|
| `pageEntryLimit` | 12 | 一个分类超过这么多条 |
| `bookEntryLimit` | 40 | 整本超过这么多条 |

**只要有一条踩线**，这次改写就会额外收到一条**强制整理令**，写明现在多少条、哪几个分类超了，并要求做三件事：

1. **合并**——同一件事、同义或高度相关的条目合成一句
2. **缩略**——啰嗦的长条目压成一句话，只留结论
3. **加小节**——条目多的分类用 `##` 拆开（比如「主人」下面按 语音 / 游戏 / 习惯 分节），不要二十多条平铺

**没踩线时不会加这段**，改写保持轻量。喂给模型的现状里也会标出每条挂在哪个小节（`{语音} …`），方便它判断哪些该合并、哪些该拆节。

## 模型每个会话看到什么

后台半注册了一个系统提示 section，**每次组装实时读盘**：按重要度取前 N 条，每条压成一行，附分类标题，再加一句「要更多就用 memoir_recall 查」。

没有记忆时这一块是空的，不占位置。

## 配置

`cordis.patch.yml` 里可以改（部署可变项都在这里，代码里没有写死的阈值）：

```yaml
- id: memoir
  name: 'dsh-memoir'
  config:
    memoryDir: ''              # 留空 = $DSH_HOME/memoir
    injectIndex: true          # 是否注入「记忆目录」
    maxInjectEntries: 12       # 注入最多几条
    autoDistill: true          # 每轮结束自动改写
    distillDebounceMs: 20000   # 改写前的安静等待
    distillMinChars: 400       # 少于这么多字符就跳过
    distillMaxItems: 60        # 整本条目上限（提示模型控制规模）
    distillMaxTokens: 8000     # 输出预算下限（会按记忆规模自动往上抬）
    distillReasoningEffort: off # 改写不需要推理，关掉思考把预算全留给正文
    pageEntryLimit: 12         # 单个分类超过这么多条 → 触发强制整理
    bookEntryLimit: 40         # 整本超过这么多条 → 触发强制整理
```

## 改代码之后

pnpm 用 `file:` 装本地包时是**硬链接**，用编辑器改写源文件会断开链接，安装位置的副本就不再更新。所以改完源码跑一次：

```powershell
& .\scripts\sync.ps1
```

它只复制真正变化过的文件，并提醒你重启客户端——**热加载只在安装插件那一刻发生**，之后改文件客户端不认。

⚠ `sync.ps1` 必须保持 **UTF-8 with BOM** 编码：这台机器上是 Windows PowerShell 5.1，它按 GBK 读没有 BOM 的脚本，中文注释会让它直接解析失败。用编辑器另存时注意选带 BOM 的 UTF-8。

## 安装

```powershell
& '<DeepSeek Harness 安装目录>\resources\runtime\cli\bin\dsh.cmd' plugin --profile desktop add '@yansera/dsh-memoir'
```

从本机源码装（开发用）：

```powershell
& '<DeepSeek Harness 安装目录>\resources\runtime\cli\bin\dsh.cmd' plugin --profile desktop add 'file:D:\deep work place\dsh-memoir'
```

包内自带 `cordis.patch.yml` 并声明了 `dsh.bundle.patch`，所以它会作为标准 profile bundle 自动挂载——**不要**再往 profile 的 `cordis.patch.yml` 手写挂载行，那会造出两个 loader entry 并中止启动。

装完后需要重启客户端才会加载。

## 自测

四个离线脚本都不依赖 DSH 宿主，也不碰任何真实 profile（共 **199 项**）：

```sh
npm test                # 全部
npm run test:store      # 存储层：解析、去重、移动、搜索、截断、注入文本
npm run test:plugin     # host 端：注册面、工具执行、系统提示、HTTP 路由
npm run test:client     # 页面半：用 React 替身渲染真 bundle，模拟点击并断言请求
npm run test:distill    # 自动改写：输出解析、防抖、游标、失败重试、容量触发
```

跑之前需要在包目录下能解析到 `@deepseek-ai/schemastery` 与 `@deepseek-ai/dsh-tools`（装进 profile 后天然满足）。

另有一个**对着运行中的客户端**跑的冒烟，会真的写一条再删掉：

```sh
npm run smoke                                       # 默认打 127.0.0.1:19387
node scripts/smoke-live.mjs http://127.0.0.1:3080   # 换端口（Web 端）
```

它顺便报出客户端加载的是哪一版代码——看 `/state` 的 `runtime` 字段在不在。插件路由不需要 GUI 的 token（只有首页 `/` 要），所以能直接跑。

## 结构

| 文件 | 作用 |
|---|---|
| `src/index.js` | 后台半：存储层、模型工具、系统提示注入、`/api/dsh-memoir/*` 路由 |
| `src/distill.js` | 每轮结束后的自动改写（按会话游标、防抖、全局串行、容量触发） |
| `src/client.js` | 页面半：侧边栏入口 + 整屏记忆册（手写 ModuleLoader bundle，无构建步骤） |
| `cordis.patch.yml` | bundle patch 层 |
| `scripts/sync.ps1` | 改完源码后同步到 profile（pnpm 的硬链接会断，必须同步） |
| `docs/` | [设计说明](docs/design.md) · [存储格式](docs/storage-format.md) · [配置](docs/configuration.md) |
| `test-*.mjs` | 四个离线自测 |
| `smoke-live.mjs` | 对运行中的客户端做真实端到端冒烟 |
